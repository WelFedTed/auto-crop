## Context

ADR-0005 proved a hand-written libheif binding in a throwaway spike and decided to bind libheif inside the codecs crate. Until now `codecs` only *recognised* HEIC and AVIF ("avif files cannot be decoded in this build"). The plan (PLAN 3.4) reads AVIF through the same libheif with dav1d, and HEIC through libheif with libde265 as a plugin.

## Decision

1. **Cargo feature `heif`, default off** in `auto-crop-codecs` (forwarded by `auto-crop-engine`, `auto-crop-cli`, `auto-crop-shell` and `xtask` as `heif`). Off, nothing native is searched for or linked and `cargo build` needs no C toolchain (`heif.yml` proves it: a prefix that does not exist, no `heif`/`dav1d`/`de265` in the test binaries, and the feature without a library fails with a pointer to `cargo xtask build-native`).
2. **Own FFI, ported from `spikes/heic`**, under `crates/codecs/src/heif/ffi/` (the one directory with `unsafe`; `ci-guards` checks the `// SAFETY:` comments). About two dozen libheif functions, RAII wrappers (`Context<'a>` borrows the input bytes because `read_from_memory_without_copy` keeps a pointer, `Handle`, `Image`, `Options`). The constants and the field order of `heif_security_limits` and `heif_decoding_options` are checked against the pinned headers by the tests, and the struct offsets were cross-checked once with `offsetof` in MSVC against the 1.23.5 headers.
3. **Header walk without the backend** (`parse/heif.rs`, safe Rust, always built): `probe` answers for HEIC and AVIF in every build (stored size after `clap`, depth from `pixi`/`av1C`/`hvcC`, orientation from `irot` and `imir`, ICC span, nclx, codec, number of top-level images, sequence frames from `moov`). Boxes visited, items (`max_frames`), references and Exif/XMP item sizes (`max_metadata_bytes`) are capped; a box that overruns its parent is `Corrupt`.
4. **Limits before pixels**: file size cap; header walk (item and metadata caps); pixel cap and memory estimate on both the `ispe` size and the cropped size (a header claiming 60000 x 60000, or a grid canvas of that size, is `TooLarge` without libheif seeing the file); then libheif with `heif_security_limits` **tightened** (only ever lowered, never zero: zero means unlimited) to `max_pixels`, the metadata cap and the memory estimate; then the primary image's size is checked again from libheif's own `width/height/ispe` numbers; the output buffer is a fallible reservation. Deadline: `max_decode_ms` becomes libheif's cancel callback (`CodecError::DecodeTimeout`).
5. **Orientation applied once.** libheif applies `clap`, `irot` and `imir`; the raster is upright; `Decoded::exif_orientation` reports the EXIF-equivalent value of what was applied (and `Probe::orientation` the same value for the stored size), so oriented sizes agree between probe and decode. The Exif tag of a HEIF file is never read (a fixture with Orientation 6 and no `irot` decodes unrotated, orientation 1). `decode_scaled` does not turn HEIF a second time. `imir` axis 0 is a top-bottom flip, axis 1 left-right: that is what libavif and libheif write and read (ISO/IEC 23008-12 words it ambiguously); the fixtures made by libavif pin it.
6. **Colour and depth**: 8-bit RGB (or RGBA, alpha dropped with `alpha.dropped` when some pixel is translucent, as for PNG and WebP); more than 8 bits are reduced by libheif (`depth.reduced_to_8`, `source_bit_depth` keeps 10 or 12); the input's own nclx matrix and range are kept (`output_image_nclx_profile_passthrough`) so no gamut conversion happens behind our back; the ICC profile comes back byte-exact; PQ and HLG sources are **not** tone-mapped yet (`hdr.not_tonemapped`), and an nclx-only wide-gamut file gets `colour.nclx_not_srgb` (M6.29/M6.30 own the real handling).
7. **Multi-image and sequences**: the primary (first) image, with `heic.multi_image`, `heic.sequence` (HEIC) or `anim.first_frame_only` (AVIF sequence); `Decoded::frames` is libheif's top-level count.
8. **Typed errors**: `CodecError::HevcDecoderMissing` (libheif code 11 / subcode 6003 for an HEVC item, or the plugin missing before the decode starts; engine `ErrKind::HevcDecoderMissing`), `UnsupportedFeature` for AVC, JPEG, JPEG 2000, VVC items and missing AV1 decoder, `LimitExceeded`/`TooLarge` for libheif security limits, `Corrupt` for damaged data, `DecodeTimeout`. Everything runs under `guard_item` (panics become `InternalPanic`); the cancel callback cannot unwind into C.
9. **Native build**: `cargo xtask build-native` builds dav1d 1.5.4 with meson (shared, no tools or tests) before libheif, which is configured with `WITH_DAV1D=ON` (dav1d linked, not a plugin); every encoder and every other decoder stays off. `check-native` additionally rejects AV1 encoder symbols and a libheif that does not link dav1d; `packaging/allowed-libs.txt` allows `dav1d`. dav1d needs meson, ninja and, on x86, NASM; macOS arm64 needs no NASM.
10. **Writers do not exist, so nothing here may replace such a source** (PLAN 3.2.3). The engine opens WebP, TIFF, AVIF, HEIC and HEIF when the build can decode them, and `save_items` refuses `Replace` for any source whose format has no writer (`ErrKind::UnsupportedOutput`; the source stays byte-identical, no temp file, no backup). `Copy` writes `AutoCrop/<stem>.png` (`.jpg` for HEIC, the conversion target of PLAN 3.5) carrying the ICC profile. There is no output-format choice in the engine yet, so this is the only copy format for these sources.

## Consequences and open items

- **Not done**: encoding (AVIF, HEIC) is out of scope; `mif3` "mini" files are a typed `UnsupportedFeature` (libheif could decode them, the header walk does not read the bit-packed `mini` box); no HDR tone-mapping, wide-gamut conversion, gain-map or depth handling (M6.24, M6.29, M6.30); alpha is dropped, not flattened on white (M6.31); no thumbnail-first draft; the sandboxed worker pool and the `HeicBackend` trait of `core::ports` are not wired (the engine calls `codecs::decode` in-process); no `heic.engine = system` path; packaging (DLL and plugin placement, rpaths, `heif::configure`) is a later task, see [heif-native.md](../testing/heif-native.md).
- **Threads**: dav1d and libde265 use every core by default; `heif::set_codec_threads` lowers it (12 MP AVIF, dev machine, release: see Results).
- **Diagnostics**: dav1d logs `Error parsing OBU data` lines to stderr for damaged files; libheif's API gives no way to silence them.
- **Revisit trigger**: a libheif or dav1d security release (bump the pin; `native-watch` tracks both), `mini` files in the wild, or the plan's HEIC engine setting (`system`) needing a trait seam.
